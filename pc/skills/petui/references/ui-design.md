# PetUI 界面设计与验收

以 **640×480 横向** 设计组件。用户的风格偏好和参考图优先，构图、素材和反馈围绕组件的用途展开。实现前先给用户确认 UI。简单组件看首屏和主操作，复杂组件按需展示关键状态。

## 设计

- **把面积留给主要内容。** 宠物突出角色轮廓、表情和姿态，给道具和动作留空间。游戏优先保证操作区和关键目标清晰。工具可以让时间、比分、图表或正文成为视觉中心。对齐信息和操作，用分隔与留白组织画面，有独立内容或操作的区域再用卡片。
- **用题材决定视觉语言。** 背景、主体、状态和主操作应有明确的明暗层级。插画、像素画、几何构成、数据图表或便签排版都可用于合适的题材。统一图标线宽、圆角和留白，让场景细节服务氛围或信息。缩到组件卡片大小时，仍能识别主体或用途。
- **按实际字宽排版。** 可从主标题 36–48 px、主按钮 22–28 px、辅助文字 18–22 px 起步，根据题材与内容调整。常用触控区尽量达到 48×48 px，操作提示留足行高。用最长有效标题、状态和读数检查换行、裁切和对齐。计时和比分可用等宽数字，避免数值变化时左右跳动。原生 WASM 的 `hachi_text` 支持 12–48 px，需要更大数字时可用 `petui sprite` 编码原尺寸数字和分隔符，再用 `hachi_sprite` 按当前值绘制。
- **按动态范围准备素材。** 生成或绘制素材时定好尺寸、主体比例、背景和文字留白。需要独立变化的角色、道具和前景分层制作，动态文字和反馈交给运行时绘制。检查设备格式转换后的 RGB565 对比度、透明边缘和暗部细节。按各运行模式的契约选用图片、音频和视频。
- **让反馈跟着动作发生。** 控件写当前动作，例如「开始」「孵化」「撤销完成」。能取得实际映射时显示当前键位，否则用动作名。让选中、不可用和成功状态可区分，保持操作位置稳定。宠物可用进食表情，游戏可用命中反馈，工具可用状态或进度变化。适合题材且能力允许时可加入短音效或动效，信息仍能通过画面读懂。

## 验收

1. 打包前准备 `pc/cover.png`。优先用运行帧，需先构建才能取帧时可用 640×480 设计稿作临时封面。
2. 在实际运行时检查首屏和主操作。简单组件看到一次主操作结果即可完成画面检查。复杂组件选择能改变体验的状态，例如暂停、结算、录音结束或数据缺失。用组件实际绑定操作，涉及触控时检查热区。WASM 按 [回放指南](hachiapp.md#wasm-执行预算验收) 执行所需回放。
3. 按需对照设计稿检查字形、层级、色差和反馈。长内容用最长有效值，循环动画可观察两个周期，持续状态可回放到短反馈消退后。发现问题时用同一状态和操作复跑。实体键、触屏、声音或性能影响实际体验时，在可用的目标设备上验证相应项目。分别记录包校验、本地试玩与实机结果。
4. 从实际运行画面取 640×480 PNG 封面，隐去私人数据并检查缩略图可读性。替换临时封面后重新打包、校验，再按原流程发布。
